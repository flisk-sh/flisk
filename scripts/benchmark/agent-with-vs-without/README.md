# Coding agent with vs without Flisk

Gives the same prompt to the same headless coding agent (`claude -p`, one fixed model) in two fresh, empty folders and measures what it takes to get the app running on this machine:

- **flisk**: the pinned Flisk version is on `PATH`, and the Flisk agent skills (`flisk-build`, the `flisk-recipe-*` recipes, `flisk-doctor`, `flisk-up`, `flisk-resource`, `flisk-status`, `flisk-troubleshoot`, `flisk-agent-ops`) are copied into the folder's `.claude/skills`.
- **no-flisk**: `flisk` and its old names (`tdk*`) are removed from `PATH`, and there are no skills. Docker, Tilt, Node, Bun and everything else on the machine stay available, so the agent can get the app running any way it likes.

The prompt text is identical in both arms. It does not mention Flisk. Both arms get the same last paragraph, which asks the agent to write every service's health URL to `HEALTH_URLS.txt` and to leave the app running.

## Run it

```bash
node scripts/benchmark/agent-with-vs-without/run.mjs                 # 2 prompts × 2 arms × 3 runs
node scripts/benchmark/agent-with-vs-without/run.mjs --runs 1 --prompts shop
```

Needs Docker running, Tilt, `curl`, Node.js 22+, and the `claude` CLI signed in with API credit (each run costs roughly a few dollars; `--budget-usd` caps one run, default 8). It installs `@flisk-sh/flisk@<--flisk-version>` (default 1.4.2) into `--workdir` (default `~/.cache/flisk-agent-bench`, which must not contain spaces) and never touches a global install.

| Flag | Default | Meaning |
| --- | --- | --- |
| `--prompts` | `shop,ai-agent` | Prompt ids from `prompts.json` |
| `--arms` | `flisk,no-flisk` | Arms to run |
| `--runs` | `3` | Runs per prompt and arm |
| `--model` | `claude-sonnet-5-5` | Model passed to `claude --model`, the same for every run; the model id the agent reports is recorded per run |
| `--flisk-version` | `1.4.2` | npm version for the flisk arm |
| `--timeout-min` | `30` | A run that has not finished is stopped and recorded as failed |
| `--budget-usd` | `8` | `claude --max-budget-usd` per run |
| `--out` | `docs/benchmarks/results/agent-with-vs-without-flisk-<date>` | Results folder |

A run that already has `raw/<id>/metrics.json` in `--out` is skipped, so an interrupted benchmark continues where it stopped. The arm that goes first alternates between runs, so warm Docker caches do not always favour the same arm. Then:

```bash
node scripts/benchmark/agent-with-vs-without/summarize.mjs <results-dir>   # summary.json, summary.md
node scripts/benchmark/agent-with-vs-without/chart.mjs <results-dir>       # chart.svg, chart.png (1270×760, needs rsvg-convert)
node --test scripts/benchmark/agent-with-vs-without/lib.test.mjs
```

`run.mjs` calls `summarize.mjs` at the end.

## What is measured

| Metric | How |
| --- | --- |
| Time to healthy | From starting the agent until every URL in `HEALTH_URLS.txt` answers: HTTP 2xx for `http(s)://`, an open TCP port for `postgres://`, `redis://` and similar. Polled every 5 s while the agent runs and checked once more after it exits. Only successful runs have one. |
| Agent wall time | From starting the agent until it exits |
| Tokens and cost | `modelUsage` and `total_cost_usd` from the agent's final `result` event: input, output, cache read and cache write tokens, summed over every model the agent used |
| Turns | `num_turns` from the `result` event |
| Infra/config files hand-written | Unique files the agent itself wrote or edited (Write, Edit, MultiEdit, or a shell `>`/`>>`/`tee`) whose name marks them as run configuration: Dockerfiles, Compose files, Tiltfiles, `.star`, nginx/Caddy/Traefik config, `.env*`, Procfile, Makefile, pm2/supervisor config, `service.json`, start/run shell scripts, or anything under `.autogenerated/`. Files a CLI generated (for example `flisk resource`) do not count, because the agent did not write them. |
| Tool errors | Tool results marked as errors (for example a command that exited non-zero) |
| Retries after an error | Tool errors that were followed by another tool call, that is, the agent tried again |
| Success | The agent finished on its own within the time limit, without an error result, `HEALTH_URLS.txt` lists at least `minServices` URLs (2 for the shop, 3 for the AI agent), and all of them answer after the agent exits. Runs are headless with no human input, so every success is without human help. |

After each run the harness stops what it started: `flisk down --prune-networks` in the flisk arm, then in both arms every process whose working folder is inside the run folder, and the Docker containers and networks created during the run. Nothing that existed before the run is touched.

## Guard rails and limits

- The agent runs with `--permission-mode bypassPermissions`, because nobody is there to approve commands. Run it on a machine where that is acceptable. Both arms deny `sudo`, global package installs, `brew`, `docker * prune`, web search and web fetch.
- The agent starts with a clean environment (`HOME`, `USER`, `LOGNAME`, `SHELL`, `TERM`, `LANG` and the arm's `PATH` only), so variables from the shell or app that started the harness, such as `ANTHROPIC_BASE_URL` or `CLAUDE_CODE_*`, do not reach it. Sign the CLI in first with `claude auth login`.
- `--setting-sources project --strict-mcp-config` keeps your user settings, plugins and MCP servers out of the runs. A user-level `CLAUDE.md` or skills in `~/.claude/skills` may still be loaded by the CLI; they apply to both arms equally. Each run records the skills the agent saw (`skillsSeenByAgent`) and the ones it used (`skillsInvoked`), so check them.
- The health URLs are the ones the agent wrote. The harness checks that they answer, not that the shop takes orders. Read `transcript.jsonl.gz` before quoting a run.
- Docker image caches are not cleared between runs (that would also clear your own images). The first run of each arm pulls base images; the alternating order spreads that cost.
- Committed transcripts are cut (long outputs shortened) and have the home folder replaced by `~`. Review them before publishing; the full streams stay in `<workdir>/raw/`.

## Results

Each benchmark is committed to `docs/benchmarks/results/agent-with-vs-without-flisk-<date>/`: `summary.md`, `summary.json`, `environment.json`, `chart.png` and one `raw/<prompt>-<arm>-<n>/` folder per run.
