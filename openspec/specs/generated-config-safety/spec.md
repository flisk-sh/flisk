## ADDED Requirements

### Requirement: Regeneration writes only TDK-owned generated paths
Generated service artifacts SHALL be written under `.autogenerated/`, except for existing project-level Tilt files already owned by Flisk. `flisk config regenerate` SHALL NOT modify files outside this generated set.

#### Scenario: User source file survives regeneration
- **WHEN** a user edits `src/index.ts` and runs `flisk config regenerate`
- **THEN** the source file remains byte-identical

### Requirement: Config verification detects generated drift
`flisk config verify` SHALL compare generated files with the output derived from `service.json` and `.tdk/project.json`. It SHALL exit 1 and identify the drifted path when a generated file differs.

#### Scenario: Generated Dockerfile was edited
- **WHEN** a generated Dockerfile differs from the expected output
- **THEN** `flisk config verify` reports its path and exits 1

#### Scenario: Generated files match their source configuration
- **WHEN** all generated files match the output derived from the service and project configuration
- **THEN** `flisk config verify` exits 0

### Requirement: Official example CI verifies generated configuration
The official example CI workflow SHALL run `flisk config verify` so generated-file drift is checked before changes are accepted.

#### Scenario: Example configuration drifts in a pull request
- **WHEN** a generated file in the official example differs from configuration
- **THEN** the verification step fails the CI job
