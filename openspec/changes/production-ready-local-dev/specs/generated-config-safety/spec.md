# Spec Delta

## Purpose

The existing regenerate and verify commands produce stable bytes.

## ADDED Requirements

### Requirement: Generation is deterministic
Given the same `.tdk/project.json`, Flisk version, and generator inputs, `flisk config regenerate` SHALL produce byte-identical generated files. It SHALL NOT write `service.json`. Generated files SHALL NOT contain timestamps, random identifiers, machine-specific absolute paths, or ordering that depends on filesystem or environment iteration order.

#### Scenario: Two regenerations match
- **WHEN** `flisk config regenerate` runs twice without input changes
- **THEN** the generated files are byte-identical and `flisk config verify` exits 0

### Requirement: Generated files identify their source
Every generated artifact SHALL include a header that says it was generated by Flisk, names its source, says not to edit it by hand, and says to regenerate with `flisk config regenerate`.

#### Scenario: Developer opens a generated Dockerfile
- **WHEN** a generated Dockerfile is opened
- **THEN** the header includes `Generated by Flisk` and `flisk config regenerate`

### Requirement: Verify names every drifted path
`flisk config verify` SHALL list each drifted generated path and SHALL tell the user to run `flisk config regenerate`. It SHALL exit 1 if any generated file differs and 0 if none differ. A second verify on unchanged files SHALL exit with the same code.

#### Scenario: Two generated files differ
- **WHEN** a generated Dockerfile and a generated Tilt file differ
- **THEN** verify names both paths, mentions `flisk config regenerate`, and exits 1
