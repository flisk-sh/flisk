# Flisk up

Start local services from `service.json` manifests. Flisk writes the Docker and Tilt configuration; do not write Dockerfiles, Tiltfiles, or routes by hand.

## Workflow

1. Run `flisk doctor` if the machine has not been checked yet. Stop on unresolved errors.
2. Preview the stack: `flisk up <stack> --dry-run`. Show the user which services and URLs will start.
3. Start it: `flisk up <stack>`. Omit `<stack>` to start every stack.
4. Confirm health with `flisk status --json`. Report each service's URL only after it reports healthy.
5. If `flisk up` refuses to start because generated files differ from `service.json`, regenerate from the source manifest. Use `--ignore-drift` only when the user asks to start anyway.

## Guardrails

- Ask before starting a large stack or one likely to build many images; cold builds can take several minutes.
- Use `flisk up -f` only when the user agrees to kill the existing Tilt process.
- Do not edit `.autogenerated/` or other generated output. Change `service.json` instead.
- Flisk runs locally. Do not use it to deploy to a cluster.
