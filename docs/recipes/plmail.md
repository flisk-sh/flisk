# Running plMail with Flisk

[plMail](https://github.com/karatektus/pl_mail) is a self-hosted mail client that ships a `compose.yaml` (secrets-init, php,
worker, database, and ntfy behind the `push` profile). Its maintainer supports Docker Compose as the one install path and
does not carry any Flisk files in their repository (karatektus/pl_mail#467). This recipe is community-maintained by the Flisk
project: it leaves plMail's files untouched and generates everything on your side from a release tag.

## Setup

Clone a release tag (not `main`) into a directory named `pl_mail`, import it, and start it:

```bash
git clone --depth 1 --branch v0.4.1 https://github.com/karatektus/pl_mail pl_mail
cd pl_mail
flisk import --yes
flisk up pl-mail
```

`flisk import` writes only `.flisk/` and `services/pl-mail/`. `compose.yaml` and the committed `.env` stay as they are, so
`git status` shows no modified file. Open `http://localhost` (or the `HTTP_PORT` you set): `/` redirects to `/login`.

To get a standalone Compose file that runs without Flisk:

```bash
flisk export compose
docker compose --env-file .env -f .autogenerated/docker-compose.yml up -d
```

## What is kept from `compose.yaml`

- Volume names. The directory is called `pl_mail`, so volumes are `pl_mail_database_data`, `pl_mail_app_secrets` and so on,
  the same names `docker compose up` uses. Data from a Compose install is picked up by Flisk and the other way round.
  Use a different directory name and the volume names change with it.
- The worker's `mercure` network alias, `stop_grace_period: 30s`, `init: true` and its disabled healthcheck.
- The `push` profile on ntfy: `flisk up pl-mail` leaves it out, as `docker compose up` does.
- Variable host ports such as `${HTTP_PORT:-80}`, and literal values such as `APP_ENV: prod`.
- `depends_on` conditions (`service_healthy`, `service_completed_successfully`).

## Limits

- Compose does not restart `database`; Flisk restarts it (`unless-stopped`). The importer prints this as a note.
- `php` publishes several ports (80, 443 and 443/udp), so Flisk does not route it through Traefik. It stays published on the
  host ports from `compose.yaml`.
- `compose.yaml` uses the `latest` image. Pin `ghcr.io/karatektus/pl_mail` to the tag you cloned if you need a fixed version.

## How it is checked

The journey [`tests/e2e/journeys/plmail`](../../tests/e2e/journeys/plmail/run.sh) clones the newest plMail release tag, runs
`flisk import --yes`, checks that no tracked file changed and that every item in the list above survived, runs
`flisk export compose --check` and `docker compose config` on the result, then runs `flisk up` and waits for `/` to redirect
to `/login`. It runs on pull requests that touch the importer or exporter, nightly, on release and on demand. When a new plMail
tag breaks the import, that journey fails; pin a known-good tag with `PLMAIL_TAG=v0.4.1` while it is fixed.
