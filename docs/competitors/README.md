# Competitor feature matrices

What other tools offer that Flisk could reasonably offer too, built from public pages and scored without a model. Read the
combined view in [MATRIX.md](MATRIX.md) (generated). It is the maintainers' reading of public pages on the `checked`
dates, not an endorsement or a benchmark.

| File | What it holds |
| --- | --- |
| `index.json` | The competitors (`id`, `name`, `url`, `category`, `why`, `watch`) and the closed list of feature `areas`. |
| `<id>.json` | One competitor's rows. |
| `labels.json` | The GitHub labels the issue sync may create, when missing and only with `--apply`. |
| `MATRIX.md` | Generated by `node scripts/competitor-matrix.mjs`; `--check` fails when it is stale. |

`watch` lists public pages of the competitor (features, changelog, pricing, docs) that fetch fine and that the competitor's
`robots.txt` allows. Today they are a record for a maintainer re-reading the sources; no job fetches them yet.

## A row

```json
{
	"id": "kebab-case-id",
	"name": "Short feature name (3 to 6 words, used in the issue title)",
	"area": "one of index.json areas",
	"offer": "What the competitor offers, one sentence, in your own words.",
	"source": "https://the-exact-page-you-read",
	"checked": "2026-10-27",
	"match": ["lower-case words the page uses for it"],
	"flisk": {
		"status": "covered | partial | missing | out-of-scope",
		"scope": "in (out for out-of-scope)",
		"reason": "required unless covered; for missing: why it may fit Flisk",
		"evidence": [{ "file": "path" }, { "command": "flisk doctor" }, { "mcpTool": "stack_list" }, { "text": { "file": "README.md", "contains": "..." } }]
	},
	"acceptance": "missing only: which evidence would prove it covered",
	"ice": { "impact": 6, "confidence": 7, "ease": 5, "basis": "why these numbers" }
}
```

- Never write a row from memory: cite the page you read and the date.
- `covered` and `partial` rows need evidence that passes today; `missing` and `out-of-scope` rows have none. The scorer
  `competitor-coverage` fails a stale claim.
- `out-of-scope` is a decision, not a gap (a terminal emulator, a hosted control plane, Kubernetes). It never becomes an issue.
- `checked` older than 90 days is a finding: re-read the source and move the date.

## ICE and the quick-win bar

Every in-scope `missing` row carries `ice`. Each number is an integer from 1 to 10:

- **impact**: how much it helps people running local multi-service and agent systems, given what the competitor's users ask for.
- **confidence**: how sure the research is (source quality, how well it maps to Flisk).
- **ease**: how little work it is given the existing code; name the file or area. 7 or more means a small change in an existing place.

ICE score = the mean of the three, one decimal. `scripts/competitor-gap-issues.mjs` opens an issue only when the score is
7.0 or more **and** ease is 7 or more (`--min-ice`, `--min-ease`). Lower rows stay in the report, listed in MATRIX.md.

## The issue sync

`node scripts/competitor-gap-issues.mjs` is a dry run. `--apply` writes: at most 5 new issues per run (`--max-new`), one per
row with the marker `<!-- competitor-gap:<competitor>:<row> -->`, labels from `labels.json` (missing ones are created, existing
ones never edited), the Feature issue type when the org has it. It never reopens an issue a maintainer closed and never touches
an issue without the marker. The body follows `.github/ISSUE_TEMPLATE/competitor-gap.yml`. The weekly workflow
(`competitor-gap-issues.yml`) is a dry run until its `SCHEDULE_APPLY` line is changed.

## Add a competitor

1. Add it to `index.json` with a `category` (`terminal-ade`, `agent-platform`, `local-dev-runtime`, `orchestrator`,
   `skills-directory`), a `why`, and `watch` pages.
2. Create `<id>.json` with `{ "competitor": "<id>", "rows": [...] }`: 15 to 30 rows read from its own docs.
3. Add `competitor: <id>` to `labels.json` and the name to the `competitor` dropdown of `.github/ISSUE_TEMPLATE/competitor-gap.yml`
   (a test keeps them in sync).
4. Run `node scripts/competitor-matrix.mjs`, `node scripts/scores/run.mjs --only competitor-coverage` and raise the baseline by hand
   if the mean moved up.
