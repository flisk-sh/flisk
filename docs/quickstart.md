# Quickstart guide

This guide walks you through getting a running local stack with Flisk. Start here if you're new to Flisk.

## Before you begin

### Prerequisites

| Tool | Minimum version | Install | Install path |
|------|----------------|---------|--------------|
| **Docker** | Engine 25+, Compose 2.20.2+ | [docker.com](https://www.docker.com/products/docker-desktop/) | All paths |
| **Tilt** | 0.25+ | `curl -fsSL https://raw.githubusercontent.com/tilt-dev/tilt/master/scripts/install.sh \| bash` | All paths |
| **Node.js** | 22.12+ | [nodejs.org](https://nodejs.org/) | npm path (`npm install -g @flisk-sh/flisk`) |
| **Bun** | 1.2+ | `curl -fsSL https://bun.sh/install \| bash` | Bun path (`bun add -g @flisk-sh/flisk`) |

> **Conditional prerequisites**: Node.js is only required when you install Flisk via npm (`npm install -g @flisk-sh/flisk`). Bun is only required when you install via Bun (`bun add -g @flisk-sh/flisk`) or your project has generated JavaScript services. Docker and Tilt are required for every path.

### Verify prerequisites

```bash
docker version
docker compose version
tilt version
node --version
bun --version
```

All should print version info without errors. Skip the check for a tool you don't use on your chosen install path.

> **Windows users**: Use WSL2 Ubuntu. See the [Windows & WSL2 guide](wsl2.md) for the recommended setup. Native Windows supports inspection commands only (`flisk --version`, `flisk doctor`, `flisk up --dry-run`); `flisk up` refuses with WSL2 guidance.

## Path 1: One-command demo (fastest)

Best for: first look, evaluating Flisk, or a throwaway test.

```bash
npm install -g @flisk-sh/flisk
flisk demo
```

What happens:
1. Clones the starter into `~/.flisk/flisk-demo`
2. Installs service dependencies
3. Boots the full stack (Postgres, backend, frontend, NATS, Traefik)
4. Opens the frontend in your browser

Press `Ctrl+C` to stop. Run `flisk down` from the demo directory to clean up.

## Path 2: Manual project setup (full control)

Best for: building your own service structure, adding Flisk to an existing folder.

### 1. Install Flisk

```bash
npm install -g @flisk-sh/flisk
# or: bun add -g @flisk-sh/flisk
```

Verify: `flisk --version`

### 2. Create a project

```bash
mkdir my-project && cd my-project
flisk project --yes
```

This creates:
- `.flisk/project.json` — project config (edit this to enable features, stacks, etc.)
- `.env` — generated `DB_PASSWORD` and `JWT_SECRET` (added to `.gitignore`)

### 3. Add services

```bash
# Add a backend API
flisk resource api --type backend --stack main --yes

# Add a frontend (optional)
flisk resource web --type frontend --stack main --yes

# Add a worker (optional)
flisk resource worker --type worker --stack main --yes
```

Each creates a `services/<stack>/<name>/service.json` — the single source of truth for that service.

### 4. Start the stack

```bash
flisk up main
```

`flisk up` prints the URLs. Example output:

```
Flisk is up.
Tilt UI: http://localhost:10350
Services:
  ✓ api → http://api.main.localhost/api/api/health
  ✓ web → http://web.main.localhost
Stop: flisk down
Logs: flisk logs <service>
Next: flisk help  # or visit https://flisk.sh/docs
```

### 5. Verify it works

```bash
# Health check the backend
curl http://api.main.localhost/api/api/health

# Open the frontend
open http://web.main.localhost
```

### 6. Stop and clean up

```bash
# Stop the stack (containers persist for inspection)
Ctrl+C
flisk down

# Full cleanup (removes containers, networks, volumes)
flisk down --prune
```

## Path 3: Guided scaffolder (interactive)

Best for: teams who want prompts to choose service types.

```bash
npm install -g @flisk-sh/flisk
npm init create-microservices my-project
cd my-project
flisk up main
```

To skip prompts and get a default `api` (backend) + `web` (frontend):

```bash
npm init create-microservices my-project -- --yes
```

See the [`create-microservices` README](https://github.com/flisk-sh/create-microservices#readme) for all options.

## What `flisk up` does

| Step | What happens |
|------|--------------|
| 1. Validate | Checks `service.json` files, project config, Docker, Tilt |
| 2. Generate | Writes Dockerfiles, Compose, Tiltfile, nginx config to `.autogenerated/` |
| 3. Drift check | Blocks if a generated file was hand-edited (use `--ignore-drift` to bypass) |
| 4. Start Tilt | Tilt builds images, starts containers, watches for changes |
| 5. Health wait | Waits for all non-deferred resources to report ready |
| 6. Smoke checks | Runs any `smoke` steps defined in `service.json` |
| 7. Print URLs | Shows Tilt UI and routed service URLs |

## Common commands

| Goal | Command |
|------|---------|
| Interactive dashboard | `flisk ui` |
| Environment health check | `flisk doctor` |
| View service logs | `flisk logs api` |
| Restart a service | `flisk restart api` |
| Preview without starting | `flisk up main --dry-run` |
| Check config drift | `flisk config verify` |
| Regenerate configs | `flisk config regenerate` |
| Explain a generated file | `flisk config explain .flisk/.flisk-out/Tiltfile` |
| Upgrade Flisk | `flisk upgrade` |

## Windows & WSL2

Flisk runs on Windows **via WSL2 Ubuntu**. Native Windows is inspection-only.

### Recommended setup

1. Install Docker Desktop with **WSL2 backend** enabled
2. In Docker Desktop → Settings → Resources → WSL Integration → enable Ubuntu
3. Open Ubuntu (Windows Terminal → Ubuntu)
4. Install Tilt and Flisk inside Ubuntu:
   ```bash
   curl -fsSL https://raw.githubusercontent.com/tilt-dev/tilt/master/scripts/install.sh | bash
   curl -fsSL https://flisk.sh/install.sh | sh
   ```
5. Run the quickstart commands above inside Ubuntu.

See the [Windows & WSL2 guide](wsl2.md) for detailed steps, troubleshooting, and what's not supported.

## Troubleshooting

| Symptom | Quick fix |
|---------|-----------|
| `flisk doctor` fails | Run the fix commands it prints, then retry |
| Port 80/443/5432 in use | `flisk doctor` shows the owner; stop it or set `FLISK_HTTP_PORT` |
| Docker not running | Start Docker Desktop / `systemctl start docker` |
| `flisk up` refuses | Run `flisk doctor` first; it explains what's missing |
| `flisk config verify` shows drift | `flisk config regenerate` to reset, or edit `service.json` instead |
| Tilt UI not opening | Check `flisk doctor` for port conflicts; Tilt runs on 10350 by default |
| Backend health fails | `flisk logs api` to see container logs; check `DATABASE_URL` in `.env` |

Full troubleshooting: [troubleshooting.md](troubleshooting.md)
