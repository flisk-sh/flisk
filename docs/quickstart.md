# Quickstart guide

This guide gets your app running on your own computer with Flisk: every part of it (a running local stack), with links you can open in your browser. Start here if you're new to Flisk. Never written code? Read [Start here](start/first-time.md) first, and keep [Words you'll see](start/words.md) open for any word you don't know.

## Before you begin

### Prerequisites

The tools you need depend on the path you pick [below](#pick-a-path). You install Flisk with [Node.js](start/words.md#nodejs) (through [npm](start/words.md#npm)) or with Bun, so you need one of those two. The simplest path needs nothing else besides the program that runs your own code. The other three paths also need [Docker](start/words.md#docker) and [Tilt](start/words.md#tilt).

| Tool | Minimum version | Install | Install path |
|------|----------------|---------|--------------|
| **Docker** | Engine 25+, Compose 2.20.2+ | [docker.com](https://www.docker.com/products/docker-desktop/) | Full demo, full control and guided setup |
| **Tilt** | 0.25+ | `curl -fsSL https://raw.githubusercontent.com/tilt-dev/tilt/master/scripts/install.sh \| bash` | Full demo, full control and guided setup |
| **Node.js** | 22.12+ | [nodejs.org](https://nodejs.org/) | npm path (`npm install -g @flisk-sh/flisk`) |
| **Bun** | 1.2+ | `curl -fsSL https://bun.sh/install \| bash` | Bun path (`bun add -g @flisk-sh/flisk`) |

> **Conditional prerequisites**: Node.js is only required when you install Flisk via npm (`npm install -g @flisk-sh/flisk`). Bun is only required when you install via Bun (`bun add -g @flisk-sh/flisk`) or your project has generated JavaScript services. Docker and Tilt are required for every path except the simplest one, where your services run as local processes.

### Verify prerequisites

To check what is already installed, paste these [commands](start/words.md#command) into your [terminal](start/words.md#terminal). Each one asks a tool for its version number.

```bash
docker version
docker compose version
tilt version
node --version
bun --version
```

All should print version info without errors. Skip the check for a tool you don't use on your chosen install path.

> **Windows users**: Use WSL2 Ubuntu (the Ubuntu app that [WSL2](start/words.md#wsl2) installs). See the [Windows & WSL2 guide](wsl2.md) for the recommended setup. Native Windows runs `flisk demo` and projects whose services each declare a `command` as local processes, and inspects Docker projects (`flisk doctor`, `flisk up --dry-run`); `flisk up` on a Docker project refuses with WSL2 guidance.

Run your app on your own computer with one command, without Docker. This fits an app made of a few [parts](start/words.md#app-parts) (services) that each start with one [command](start/words.md#command), for example a back end (an API), a website and a worker.

Put a small settings file called `service.json` next to each part, in its folder. It tells Flisk the part's name, the command that starts it and the [port](start/words.md#port) it listens on. This one is for the back end:

```json
{
  "schemaVersion": 1,
  "appName": "api",
  "appType": "backend",
  "command": "node server.js",
  "port": 4000,
  "healthCheckPath": "/health"
}
```

This one is for the website. `"dependsOn": ["api"]` means "start the back end first":

```json
{
  "schemaVersion": 1,
  "appName": "web",
  "appType": "frontend",
  "command": "node server.js",
  "port": 3000,
  "dependsOn": ["api"]
}
```

Then start everything from the project folder. In your [terminal](start/words.md#terminal), run:

```bash
flisk up
```

What you will see: Flisk starts each part, waits until it answers, and prints the URLs (the [localhost](start/words.md#localhost) web addresses to open in your browser). If a part crashes, Flisk starts it again. To stop, press Ctrl+C (hold Control and press C).

**For developers:** each service runs as a local process. No Docker, no Tilt, no generated files. See [Run your app without Docker](run-without-docker.md) for every field.

## What `flisk up` does

On the demo, full control and guided paths, [`flisk up`](start/words.md#flisk-up) does these steps for you, in this order. You do not need to know them to use Flisk.

| Step | What happens |
|------|--------------|
| 1. Validate | Checks `service.json` files, project config, Docker, Tilt |
| 2. Generate | Writes Dockerfiles, Compose, Tiltfile, nginx config to `.autogenerated/` |
| 3. Drift check | Blocks if a generated file was hand-edited (use `--ignore-drift` to bypass) |
| 4. Start Tilt | Tilt builds images, starts containers, watches for changes |
| 5. Health wait | Waits for all non-deferred resources to report ready |
| 6. Smoke checks | Runs any `smoke` steps defined in `service.json` |
| 7. Print URLs | Shows Tilt UI and routed service URLs |

## Common commands

The commands you will use most, by what you want to do:

| Goal | Command |
|------|---------|
| Interactive dashboard | `flisk ui` |
| Environment health check | `flisk doctor` |
| View service logs | `flisk logs --service api` |
| Restart a service | `flisk restart api` |
| Preview without starting | `flisk up main --dry-run` |
| Check config drift | `flisk config verify` |
| Regenerate configs | `flisk config regenerate` |
| Explain a generated file | `flisk config explain .flisk/.flisk-out/Tiltfile` |
| Upgrade Flisk | `flisk upgrade` |

## Windows & WSL2

Flisk runs on Windows **via WSL2 Ubuntu**: the Ubuntu app that [WSL2](start/words.md#wsl2), Windows' built-in way to run Linux, installs. Outside Ubuntu, native Windows runs `flisk demo` and apps whose services each declare a `command` ([without Docker](run-without-docker.md)); a Docker stack needs Ubuntu.

### Recommended setup

1. Install Docker Desktop with **WSL2 backend** enabled
2. In Docker Desktop → Settings → Resources → WSL Integration → enable Ubuntu
3. Open Ubuntu (Windows Terminal → Ubuntu)
4. Install Tilt and Flisk inside Ubuntu:
   ```bash
   curl -fsSL https://raw.githubusercontent.com/tilt-dev/tilt/master/scripts/install.sh | bash
   curl -fsSL https://flisk.sh/install.sh | sh
   ```
5. Run the quickstart commands inside Ubuntu.

See the [Windows & WSL2 guide](wsl2.md) for detailed steps, troubleshooting, and what's not supported.

## Troubleshooting

Something not working? Run [`flisk doctor`](start/words.md#flisk-doctor) first. It checks your computer and tells you, in plain words, what is missing and how to fix it.

| Symptom | Quick fix |
|---------|-----------|
| `flisk doctor` fails | Run the fix commands it prints, then retry |
| Port 80/443/5432 in use | `flisk doctor` shows the owner; stop it or set `FLISK_HTTP_PORT` |
| Docker not running | Start Docker Desktop / `systemctl start docker` |
| `flisk up` refuses | Run `flisk doctor` first; it explains what's missing |
| `flisk config verify` shows drift | `flisk config regenerate` to reset, or edit `service.json` instead |
| Tilt UI not opening | Check `flisk doctor` for port conflicts; Tilt runs on 10350 by default |
| Backend health fails | `flisk logs --service api` to see container logs; check `DATABASE_URL` in `.env` |

Full troubleshooting: [troubleshooting.md](troubleshooting.md)

## Usability feedback (UMUX-Lite)

We use the **UMUX-Lite** two-item scale to track perceived ease of use. If you're willing to share your ratings (1–7), it helps us improve:

| Item | Your rating (1–7) |
|------|-------------------|
| "Flisk's capabilities meet my requirements" | |
| "Flisk is easy to use" | |

The form also asks one more question: how you would feel if you could no longer use Flisk (very, somewhat or not disappointed).

To submit, fill in the [Usability feedback form](https://github.com/flisk-sh/flisk/issues/new?template=usability-feedback.yml) (it takes under a minute) or post in Discord. No telemetry or automated survey is collected — this is manual and optional.

Maintainers: `node scripts/umux-lite-score.mjs` reads the form's issues and prints the number of responses and the UMUX-Lite score, `(capabilities - 1 + ease - 1) / 12 × 100`, overall and by how people built. `node scripts/scores/run.mjs --only pmf --source gh` prints the share who would be very disappointed (the Sean Ellis test; 40% is the usual benchmark). `--only umux-lite --source gh` prints the same UMUX-Lite score in the weekly scoreboard, plus, for people who also rated the tool they used before, that tool's score next to Flisk's from the same people. `--only competitors --source gh` compares public numbers (stars, release age, README reading ease) with similar tools; those are not usability scores. Quote a score only together with its `n`.
