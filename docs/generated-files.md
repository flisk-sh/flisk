# Generated service files

Write each service's `service.json`. Flisk reads it with the project configuration in `.tdk/project.json` and writes the local Docker and Tilt runtime files under that service's `.autogenerated/` directory. Tilt regenerates them when it loads the project. Edit the manifest or other source inputs, not the generated files: a later generation can overwrite hand edits.

For example, `services/store/storefront-web/service.json` is the input for `services/store/storefront-web/.autogenerated/`. The files below describe a Bun/TypeScript frontend. The exact set depends on `appType`, language, features, and project settings.

| File in `.autogenerated/` | Purpose |
| --- | --- |
| `nginx.autogenerated.conf` | Serves the built frontend and routes configured API requests. |
| `Dockerfile.app.autogenerated` | Builds the app image used by the local Docker/Tilt stack. |
| `Dockerfile.app.autogenerated.dockerignore` | Excludes files from that image's build context when the generated Dockerfile is selected. |
| `.env.frontend.autogenerated` | Supplies local frontend environment settings. |
| `env.ts` | Exports the generated API URL for frontend imports. |
| `vite.config.frontend.autogenerated.ts` | Configures the frontend dev server. |
| `vite.config.build.autogenerated.ts` | Configures the frontend production build served by nginx. |
| `tsconfig.autogenerated.json` | TypeScript settings for local development. |
| `tsconfig.docker.autogenerated.json` | TypeScript settings for the container build. |
| `.npmrc.autogenerated` | Package registry settings for the host. |
| `.npmrc.docker.autogenerated` | Package registry settings for the container. |
| `bunfig.autogenerated.toml` | Bun package settings for the host. |
| `bunfig.docker.autogenerated.toml` | Bun package settings for the container. |
| `api-client.ts` | Preconfigured client for the frontend's API route. |
| `api-index.ts` | Re-exports the generated API client and URL. |
| `AGENTS.md` | Warns coding agents that the directory is generated; the free version is a short notice. |
| `validation-report.autogenerated.json` | Records the generator's preflight validation result. |
| `service.yaml` | A generated projection of `service.json` used for Tilt resource tracking; edit the JSON instead. |

The host and container package/TypeScript config pairs account for different registry addresses and source paths; their values can be identical when both use the public registry. Keep both in the generated directory. If a service needs different behavior, change its `service.json` or the relevant Flisk generator rather than patching one output. Flisk also stores service-file snapshots under `.autogenerated/.tdk-contract/` for drift checks.

## Other service types

- A Bun backend gets `.env.backend.autogenerated`, `vite.config.backend.autogenerated.ts`, TypeScript and package configs, a Dockerfile, and a generated Prisma config in place of the frontend-only nginx, Vite frontend, and API helper files.
- Python, Go, and Rust backends use provider-owned runtime files. Flisk still generates their local Dockerfile and other applicable service outputs, but skips Bun-only Vite, TypeScript, Prisma, npm, and Bun config generation.
- Optional features add files. For example, a service with Playwright enabled gets `playwright.config.autogenerated.ts`. A bring-your-own service follows a different generation path.

## Check and repair drift

`flisk up` checks generated service files against their saved snapshot before Tilt starts. A hand edit to a generated file blocks startup and names the file. `flisk up --dry-run` runs the same check without starting containers. Editing `service.json` and running `flisk up` is the normal workflow: Flisk regenerates the service outputs from the new manifest.

`flisk config verify` checks the wider generated project contract under `.tdk/.tdk-out/`. It also validates discovered `service.json` files and compares generated service files with their saved snapshots (`service.yaml` is exempt from that comparison). Use `flisk doctor` for local readiness and discovered service issues. `flisk config regenerate` replaces generated project files; `flisk up` regenerates service files when the manifest changes. A hand-edited service file blocks `flisk up` until the edit is removed or the check is explicitly bypassed. Move any intended change into the source input first.
