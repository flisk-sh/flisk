# Generated service files

Write each service's `service.json`. Flisk reads it with the project configuration in `.flisk/project.json` and writes the local Docker and Tilt runtime files under that service's `.autogenerated/` directory. Tilt regenerates them when it loads the project. **Edit the manifest or other source inputs, not the generated files**: a later generation can overwrite hand edits.

For example, `services/store/storefront-web/service.json` is the input for `services/store/storefront-web/.autogenerated/`. The files below describe a Bun/TypeScript frontend. The exact set depends on `appType`, language, features, and project settings.

## File ownership: what you can edit vs. what Flisk regenerates

| File pattern | Owner | Notes |
| --- | --- | --- |
| `service.json` | **You** | The source of truth. Edit this to change any generated output. |
| `.flisk/project.json` | **You** | Project-level config (stacks, discovery paths, features). |
| `.autogenerated/*.autogenerated.*` | **Flisk** | Always regenerated. Hand edits are lost on next `flisk up` or `flisk config regenerate`. |
| `.autogenerated/.flisk-contract/` | **Flisk** | Snapshots for drift detection. Do not edit. |
| `.autogenerated/service.yaml` | **Flisk** | Projection of `service.json` for Tilt. Edit `service.json` instead. |
| `.env` (project root) | **You** | Runtime secrets and overrides. Not regenerated. |
| `package.json` (service) | **You** | Your dependencies and scripts. Flisk adds required scripts on `flisk resource`; preserve them. |

**Rule**: If a file ends in `.autogenerated.*`, Flisk owns it. Change the source (`service.json`, `.flisk/project.json`, templates) instead.

## Frontend (Bun/TypeScript) — files grouped by purpose

### Runtime configuration (Docker, nginx)
| File in `.autogenerated/` | Purpose | Regenerated on `service.json` change |
| --- | --- | --- |
| `nginx.autogenerated.conf` | Serves the built frontend and routes configured API requests. | Yes |
| `Dockerfile.app.autogenerated` | Builds the app image used by the local Docker/Tilt stack. | Yes |
| `Dockerfile.app.autogenerated.dockerignore` | Excludes files from that image's build context. | Yes |

### TypeScript & build configuration
| File in `.autogenerated/` | Purpose | Regenerated on `service.json` change |
| --- | --- | --- |
| `tsconfig.autogenerated.json` | TypeScript settings for local development (host). | Yes |
| `tsconfig.docker.autogenerated.json` | TypeScript settings for the container build. | Yes |
| `vite.config.frontend.autogenerated.ts` | Configures the frontend dev server. | Yes |
| `vite.config.build.autogenerated.ts` | Configures the frontend production build served by nginx. | Yes |

### Package manager configuration
| File in `.autogenerated/` | Purpose | Regenerated on `service.json` change |
| --- | --- | --- |
| `.npmrc.autogenerated` | Package registry settings for the host. | Yes |
| `.npmrc.docker.autogenerated` | Package registry settings for the container. | Yes |
| `bunfig.autogenerated.toml` | Bun package settings for the host. | Yes |
| `bunfig.docker.autogenerated.toml` | Bun package settings for the container. | Yes |

### Environment & generated code
| File in `.autogenerated/` | Purpose | Regenerated on `service.json` change |
| --- | --- | --- |
| `.env.frontend.autogenerated` | Supplies local frontend environment settings. | Yes |
| `env.ts` | Exports the generated API URL for frontend imports. | Yes |
| `api-client.ts` | Preconfigured client for the frontend's API route. | Yes |
| `api-index.ts` | Re-exports the generated API client and URL. | Yes |

### Metadata & tooling
| File in `.autogenerated/` | Purpose | Regenerated on `service.json` change |
| --- | --- | --- |
| `AGENTS.md` | Warns coding agents that the directory is generated. | Yes |
| `validation-report.autogenerated.json` | Records the generator's preflight validation result. | Yes |
| `service.yaml` | A generated projection of `service.json` used for Tilt resource tracking; edit the JSON instead. | Yes |

The host and container package/TypeScript config pairs account for different registry addresses and source paths; their values can be identical when both use the public registry. Keep both in the generated directory. If a service needs different behavior, change its `service.json` or the relevant Flisk generator rather than patching one output. Flisk also stores service-file snapshots under `.autogenerated/.flisk-contract/` for drift checks.

## Other service types

- **Bun backend**: Gets `.env.backend.autogenerated`, `vite.config.backend.autogenerated.ts`, TypeScript and package configs, a Dockerfile, and a generated Prisma config (instead of frontend nginx/Vite/API files).
- **Python, Go, Rust backends**: Use provider-owned runtime files. Flisk generates their local Dockerfile and applicable service outputs, but skips Bun-only Vite, TypeScript, Prisma, npm, and Bun config generation.
- **Agent / MCP / Worker**: Follow their respective patterns; see the service type reference.
- **Optional features**: Add files (e.g., Playwright → `playwright.config.autogenerated.ts`).
- **Bring-your-own (BYO) services**: Follow a different generation path; see [BYOD](byo.md).

## Check and repair drift

| Command | What it checks | Blocks on hand edits |
| --- | --- | --- |
| `flisk up` | Service `.autogenerated/` files vs. saved snapshots | **Yes** — fails and names the file |
| `flisk up --dry-run` | Same check, no containers started | **Yes** — reports what would block |
| `flisk config verify` | Project contract (`.flisk/.flisk-out/`), all `service.json`, service file snapshots | No (reports only) |
| `flisk doctor` | Local readiness + discovered services; lists each resource's `.autogenerated/` files | No (warns if not yet generated) |

**Normal workflow**: Edit `service.json` → run `flisk up` → Flisk regenerates service outputs from the new manifest.

**If a hand edit blocks `flisk up`**:
1. Move the intended change into the source (`service.json`, project config, or template)
2. Run `flisk config regenerate` (project-level) or `flisk up` (service-level) to regenerate
3. Or bypass once: `flisk up --ignore-drift` (not recommended; the edit will be lost on next regen)

**Inspect a single file**: `flisk config explain <path>` reports whether Flisk generates it, which input it comes from, and whether editing it blocks `flisk up` (`--json` for scripts).
