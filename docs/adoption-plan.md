# Plan: get public repos to adopt Flisk (`service.json`)

Status on 2026-11-01 (see *Progress* below): **1 merged** ([biolend83/tubehaus#40](https://github.com/biolend83/tubehaus/pull/40), Flisk as an option next to Compose), **1 open** ([dilolabs/nosia#386](https://github.com/dilolabs/nosia/pull/386)), 8 more in preparation toward 10.

## Decisions (Zachman, answered 2026-11-01)

| Question | Decision |
|---|---|
| **What** counts | A public repo outside `flisk-sh` that commits `service.json` **and** says `service.json` + `flisk` in its README. Nothing else. |
| **Why** | Take 1% of Docker Compose's market share. 1% is about 100,000 repos. We cannot reach that by hand. Hands-on covers at most 10 repos, so the first 10 exist to learn, then tooling scales it. |
| **How** (Compose) | Delete the hand-written `docker-compose.yml`. `flisk export compose` (in `flisk-sh/flisk-export`) writes a **standalone** Compose file from `service.json` into a committed `.autogenerated/` folder, so plain `docker compose up` still works without Flisk. `service.json` is the source of truth. First version: bring-your-own resources only. |
| **Where** | `.autogenerated/docker-compose.yml`, committed, marked do-not-edit. CI runs `flisk export compose --check` to fail on drift. The Starlark engine's own Compose (external Flisk networks, `FLISK_*` vars, required `JWT_SECRET`) is not usable without Flisk, so it is not what we commit. |
| **Who** | Anyone can open one (it is GitHub). The first 10 we do by hand, to get our hands dirty. |
| **When** | First 10 repos by 25 Nov (window of flisk-sh/flisk#1448). Scaling starts only after those 10 show a repeatable recipe. |
| **Risk** | If a maintainer rejects deleting Compose, that is our design fault, not theirs. Fix Flisk, not the maintainer. |

This supersedes the earlier "keep Compose side by side" advice: Compose stays *available* (generated), but is no longer *authored*.

## What counts, and what does not

| Counts | Does not count |
|---|---|
| Public repo outside `flisk-sh` with `service.json` | Private pilots, logos, DMs |
| README with both `service.json` and `flisk` (what repo search ranks) | A form submission alone |
| Topic `flisk` on the repo | Stars on `flisk-sh/flisk` |
| ADOPTERS.md row, after the repo exists | The "flisk vs compose" search itself |

GitHub's search for "service.json flisk vs compose" is **repository** search (name, description, README). Chasing `vs` is the wrong score.

## The PR recipe (hands-on, first 10)

```bash
flisk project --yes
flisk import .
# if import is wrong for a service:
flisk resource orders-api --type bring-your-own --stack shop --dockerfile ./Dockerfile --yes
flisk doctor
flisk up shop --dry-run
flisk up shop
```

- Commit `service.json` files, `.flisk/project.json`, and the generated `.autogenerated/` folder. Keep `.env` and `.flisk/.flisk-out/` gitignored.
- Delete the old `docker-compose.yml` only after the generated one starts the same stack.
- **Migrate existing data volumes.** Compose users have named volumes; the generated stack must reuse them (CodeRabbit's Major finding on tubehaus#40). Losing data on upgrade kills the PR.
- Add a CI step: `flisk config verify` so the generated folder cannot drift.
- README block, words intact:

```text
## Local dev

Each service has a `service.json`. Flisk starts that slice on the laptop:

    flisk doctor
    flisk up shop

Compose is generated from `service.json` into `<folder>/`; do not edit it. Flisk does not deploy. Production stays as it is.
https://flisk.sh
```

- After merge: add the `flisk` topic, then the "We use Flisk" form or ADOPTERS.md row.
- Measure time-to-first-health-URL with `scripts/pilot-scorecard.sh`. Do not send the PR if `flisk up` loses to their current get-started page.

## Gaps found and fixed (2026-11-01)

Each row was found by importing a real repo and starting the result. Fixed means merged and released.

| Gap | Fix |
|---|---|
| Container `command`/`entrypoint` on an image | flisk-import: generated `Dockerfile` (`FROM image` + `CMD`/`ENTRYPOINT`) |
| `secrets.required`, `healthcheck`, `depends_on` conditions, `on-failure` | flisk-export 0.2.1, flisk-import 0.7-0.8 |
| Existing install's volumes not reused | core `volumes[].name` (#2970), importer/exporter keep the Docker name |
| `tmpfs`, `env_file`, `deploy` limits, `profiles` | core #2968, flisk-import 0.12.0, flisk-export 0.5.0 |
| Published ports moved to 127.0.0.1 (a migrated proxy became unreachable) | flisk-import 0.11.0 keeps the host address (`bind`, or `publish` for another IPv4 / `${VAR:-default}`); flisk-export 0.4.1 writes `publish` |
| Host binding from `.env` (`TUBEHAUS_HTTP_BIND`) | core `extraPorts[].publish` (#2947, release 1.4.26) |
| Generated Compose read `.env` from `.autogenerated/` | flisk-export 0.4.2 header: `docker compose --env-file .env -f .autogenerated/docker-compose.yml up -d` |
| Compose `models` | core #2972 (in review) |

**Open (in progress):** image tags with `${VAR}`, `restart: on-failure:N`, `container.stopGracePeriod`, `container.networkAliases` (also keeps the original name of a renamed service), `container.extraHosts`, `container.ulimits`; then flisk-import 0.13.0 / flisk-export 0.6.0. **Not started:** `command` on a `build:` service, volume source `${VAR:-./path}`, `logging`, a project with only bring-your-own services still starts the router and a Postgres (#2963), `FLISK_HTTP_PORT` not read from `.env` (#2971).

Local trial setup: `node` is Bun (an `npx`/`npm` shim over `bunx`/`bun`), Colima only shares `$HOME` for bind mounts, and there is no Docker Model Runner, so `models` is stripped from test copies only.
