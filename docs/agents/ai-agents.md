# Running AI agents in TDK

TDK is the local runtime for agent **systems**: your agent process, its local state store, its MCP tool servers, databases, queues, and mock providers, running behind one gateway with one command: `tdk up`.

Instead of running agents as detached scripts or hand-rolling complex Compose files, TDK gives agents first-class local infrastructure:
- **Durable checkpoints**: Session state survives `tdk down`, container restarts, and hot reload via persistent named volumes.
- **Graceful SIGTERM drains**: In-flight LLM turns checkpoint before shutdown or live-update reloads.
- **Session routing**: Traefik routes requests by session (`x-session-id`), keeping concurrent agent conversations isolated.
- **Liveness and application readiness**: `/health` confirms process liveness. `/ready` verifies the checkpoint store for callers that need to wait before sending turns. TDK's generated health check uses `healthCheckPath`, which is `/health` in this example.

The product website already publishes a site-level [llms.txt](https://tdk-landscape.github.io/tdk-website/llms.txt). The files in this folder give agents browsing the source repository a CLI-focused contract.

## Three ways to run or use agents with TDK

### 1. The first-class `agent` resource type (Recommended)

Scaffold a dedicated agent service with durability and session management:

```bash
tdk resource bot --type agent --stack shop --yes
tdk up shop
```

This creates a Bun HTTP service in `services/shop/bot` with `service.json`:

```json
{
  "$schema": "https://tdk-landscape.github.io/tdk-website/schemas/service-schema.json",
  "name": "bot",
  "appType": "agent",
  "stack": "shop",
  "port": 4001,
  "healthCheckPath": "/health",
  "agent": {
    "runtime": "custom",
    "durability": "files"
  }
}
```

#### What you get
- **Custom runtime escape hatch**: `src/index.ts` is vendor-neutral (plain Node/Bun built-ins). Call Anthropic, OpenAI, Gemini, LangGraph, or Mastra inside `runTurn(checkpoint, input)`.
- **Files durability volume**: Checkpoints are stored in `/var/lib/tdk-agent/<sessionId>.json` on a named Docker volume (`<project>-<stack>-autogenerated_<res>-agent-state`). The volume survives `tdk down`. Remove it explicitly with `docker volume rm <project>-<stack>-autogenerated_<res>-agent-state`.
- **Session-aware turn execution**: Send a POST to `http://api.shop.localhost/api/bot/turn` with `x-session-id: session-123`. The agent loads the session checkpoint, appends the user prompt, invokes `runTurn()`, atomically commits the updated checkpoint, and returns the reply.
- **Application readiness check**: `GET /ready` verifies that the state directory is accessible and writable before callers send turns. It is not the endpoint used by TDK's generated health check in this example.

### 2. Agent as an `mcp` resource

Expose local tools, databases, and microservices to coding agents (Claude Code, Codex, Cursor) via the Model Context Protocol:

```bash
tdk resource tools-mcp --type mcp --stack shop --yes
tdk up shop
```

- Generates an MCP server built with `@modelcontextprotocol/sdk` on the Streamable HTTP transport at `/mcp`.
- Runs alongside your application services under Traefik routing at `http://api.shop.localhost/api/tools-mcp/mcp`.
- Lets external agents safely query your local database or trigger application endpoints through standardized MCP tools.
- See [docs/mcp.md](../mcp.md) for full details on tool registration and schemas.

---

### 3. TDK as the control plane via `tdk mcp`

Let your AI coding assistant orchestrate your local stack directly through MCP over stdio:

Configure `tdk mcp` in your agent's MCP settings (e.g., `~/.claude/claude_desktop_config.json` or `.cursor/mcp.json`):

```json
{
  "mcpServers": {
    "tdk": {
      "command": "tdk",
      "args": ["mcp"]
    }
  }
}
```

Now Claude Code, Cursor, or Codex can:
- Run `doctor` to diagnose container runtime or port conflicts.
- Call `up` / `down` to launch or teardown services safely.
- Read structured `status` to verify whether APIs and databases are healthy.
- Inspect `logs` with bounded windows to debug failures without dumping mega-token stack traces into context.

## Agent recipes with existing service types

If you have existing worker pipelines or custom Python/Go agents, you can also host them using standard TDK primitives:

### Recipe: Python / LangGraph agent as a `worker` with Postgres

For background agents processing task queues or event loops:

```bash
tdk resource research-agent --type worker --stack shop --yes
```

In `service.json`, add dependency links to your database or message queue:

```json
{
  "name": "research-agent",
  "appType": "worker",
  "stack": "shop",
  "dependsOn": ["postgres", "nats"],
  "env": {
    "DATABASE_URL": "@ref(postgres.DATABASE_URL)",
    "NATS_URL": "@ref(nats.NATS_URL)"
  }
}
```

The agent boots only after Postgres and NATS pass their readiness gates, receives clean database credentials, and reconnects smoothly during hot reload.

## How TDK routes agent traffic

Traefik serves as the unified local gateway for your entire agent topology:

```
                          +--------------------------+
                          |     Traefik Gateway      |
                          |   (*.localhost:80/8080)  |
                          +----------+---------------+
                                     |
              /api/bot/*             |             /api/tools-mcp/mcp
         (x-session-id sticky)       |                    |
                                     v                    v
                          +----------------+     +----------------+
                          |  agent (bot)   |     |  mcp resource  |
                          | Bun / Lang-    |     |  Tools server  |
                          | Graph / Mastra |     +--------+-------+
                          +--------+-------+              |
                                   |                      |
                                   v                      v
                          +--------------------------------+
                          |  Postgres / NATS / Backend     |
                          +--------------------------------+
```

- **Clean hostnames**: Reach your agents and APIs through `api.<project>.localhost`.
- **Zero port conflicts**: Even with dozens of tools, agents, and backends running, Traefik multiplexes everything through a single host port.
