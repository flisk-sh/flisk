# Lab 12: Work with an AI agent

**Goal:** let your coding agent drive Flisk, and know what to give it so it does not guess.
**Time:** 10 minutes. **Previous:** [Lab 11](11-more-kinds-of-service.md). **Next:** [Lab 13](13-stop-clean-up-next.md).

Flisk is built so an agent can set up and run your stack without writing Docker files. This lab shows the three ways to use that.

## Way 1: Ask in plain words

Paste a prompt into Claude Code, Codex, Cursor, GitHub Copilot, or any agent that can run commands.

```text
Use Flisk to show me which services are running, which are unhealthy, and what URL each one has.
```

```text
Run flisk doctor, explain every problem in plain words, and fix what you can. Then start my stack with flisk up.
```

```text
Add a backend service called payments-api to the shop stack with Flisk, start the stack, and give me the URLs.
```

## Way 2: Machine-readable output

Agents read JSON, not terminal text. Try these yourself so you know what your agent sees:

```bash
flisk status --json
flisk doctor --json
flisk networks --json
flisk up shop --dry-run --json
```

Each prints one JSON object. See [machine-readable CLI](../reference/machine-readable-cli.md) for the fields.

## Way 3: Connect Flisk as an MCP server

Add this to your agent's MCP settings (for example `.cursor/mcp.json`, or the MCP file for your agent):

```json
{
  "mcpServers": {
    "flisk": { "command": "flisk", "args": ["mcp"] }
  }
}
```

Your agent can then start the stack, check status, restart a service, and read agent sessions through Flisk's tools, with no shell commands. The setup is in the [AI agents guide](../agents/ai-agents.md).

## Rules to give your agent

Put these in your agent's instructions file (`AGENTS.md`, `CLAUDE.md`, or similar):

```text
- Create services with `flisk resource <name> --type backend|frontend|worker|mcp|agent --stack <stack> --yes`.
- Never edit files in .autogenerated/, .flisk/.flisk-out/, or any *.autogenerated.* file. Edit service.json instead.
- Start with `flisk up <stack>`. Check with `flisk status --json` and `flisk doctor --json`.
- Run `flisk config verify` after changing a service.json.
```

Every `.autogenerated/` folder already contains an `AGENTS.md` that tells agents not to edit it.

## Try it

1. Ask your agent: "Add a backend service called payments-api to the shop stack with Flisk."
2. Watch which commands it runs. It should use `flisk resource`, not write a Dockerfile.
3. Ask it to run `flisk config verify` and report the result.

## Checkpoint

- [ ] You ran `flisk status --json` and saw JSON.
- [ ] Your agent added a service with `flisk resource`.
- [ ] You know which folders your agent must not edit.

## Stuck?

- **The agent writes Docker or Compose files:** add the rules above to its instructions and ask it to use `flisk resource` instead.
- **The agent cannot find `flisk`:** run `which flisk` in the agent's terminal. It needs the same `PATH` as yours.
- **MCP tools do not appear:** restart the agent after editing its MCP settings.
