# Lab 9: What Flisk wrote, and drift

**Goal:** see the files Flisk generated for you, and learn why editing them by hand is blocked.
**Time:** 10 minutes. **Previous:** [Lab 8](08-logs-restart-dashboard.md). **Next:** [Lab 10](10-change-a-service-json.md).

You can do this lab with the stack running or stopped.

## Part A: Look at what Flisk wrote

1. List the generated files for your website:

   ```bash
   ls -a services/shop/shop-web/.autogenerated
   ```

2. Read how the website finds your API:

   ```bash
   cat services/shop/shop-web/.autogenerated/env.ts
   ```

3. Read the stack's Compose file, which holds the gateway routes:

   ```bash
   grep traefik services/shop/.autogenerated/docker-compose.app.autogenerated.yml | head -12
   ```

### You should see

The website folder holds about 18 files: a Dockerfile, an nginx config, Vite and TypeScript settings, `env.ts`, `api-client.ts`, and more. `env.ts` contains the API address:

```ts
export const API_URL = import.meta.env.VITE_API_URL || 'http://api.my-shop.localhost/api/shop-management';
```

The Compose file has dozens of `traefik.http.routers...` lines. Those are the routes you would otherwise write by hand.

### What this shows

Everything is linked. The website's API address is built from the same hostname the gateway routes to your API. You never copied an address from one place to another. The full inventory of generated files is in [generated files](../generated-files.md).

## Part B: Break something on purpose

1. Add a line to a generated file:

   ```bash
   echo "# my edit" >> services/shop/orders-api/.autogenerated/Dockerfile.app.autogenerated
   ```

2. Check your project:

   ```bash
   flisk config verify
   ```

3. Try to start:

   ```bash
   flisk up shop --dry-run
   ```

### You should see

```text
⚠️  Configuration issues found:
   - services/shop/orders-api/.autogenerated/Dockerfile.app.autogenerated: generated file differs from its Flisk snapshot (run flisk up to regenerate)
```

```text
❌ Generated files were edited by hand and no longer match service.json:
  services/shop/orders-api/.autogenerated/Dockerfile.app.autogenerated
Run `flisk config regenerate` to discard the edits, or bypass with `flisk up --ignore-drift`.
```

### Fix it

```bash
flisk config regenerate
flisk config verify
```

You should see `✅ All files are in sync!`. If it still lists the file, run `flisk up shop`, which regenerates service files, then verify again.

## What just happened

Flisk keeps a snapshot of every file it generates. If a file no longer matches, `flisk up` stops and names the file, so a forgotten hand edit never silently changes what runs. To change behavior, edit `service.json` (Lab 10), not the generated files.

`flisk doctor` checks your machine and running services. `flisk config verify` checks that generated files match their sources. They are different checks.

## Ask your AI agent instead

```text
Show me the generated files for shop-web and explain what each group does. Then run flisk config verify and tell me whether anything has drifted.
```

Flisk also puts an `AGENTS.md` in each `.autogenerated/` folder, telling coding agents not to edit it.

## Checkpoint

- [ ] You found the API address in `env.ts`.
- [ ] You saw `flisk up` refuse to start after a hand edit.
- [ ] `flisk config verify` is clean again.

## Stuck?

- **Still shows drift after `regenerate`:** run `flisk up shop`, which regenerates service files from `service.json`, then verify again.
- **You really need a different file:** [bring your own Dockerfile](../byo.md) instead of editing generated ones.
