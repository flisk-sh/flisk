# Topologies (Incremental Migration)

This folder holds the Starlark modules that turn `service.json` manifests into Docker Compose and Tilt resources for local development. TDK generates these for `tdk up` on your machine; it does not generate Kubernetes deployment manifests.

## How a `service.json` becomes running resources

Paths below are relative to the repository root. The order is the order things run.

1. **Generate the project Tiltfile.** `tdk up` (or `tdk config regenerate`) renders `.tdk/.tdk-out/Tiltfile` from [`cli/templates/Tiltfile.hbs`](../../cli/templates/Tiltfile.hbs). It loads the engine through the root [`Tiltfile`](../../Tiltfile), which re-exports `Manifest`, `Orchestrator`, `Infra` and the rest.
2. **Discover and validate manifests.** The generated Tiltfile calls `Manifest.load_all(...)`. Discovery, normalization and the field checks live in [`discovery/loading.star`](../../discovery/loading.star), [`discovery/json_manifest_scanner.star`](../../discovery/json_manifest_scanner.star), [`discovery/manifest/normalize.star`](../../discovery/manifest/normalize.star) and [`discovery/manifest/validation.star`](../../discovery/manifest/validation.star). Parsing helpers and constants are in [`tilt/manifest/parser.star`](tilt/manifest/parser.star) and [`tilt/manifest/constants.star`](tilt/manifest/constants.star). The `dependsOn` check you see from `tdk config verify` is in [`cli/src/commands/config.ts`](../../cli/src/commands/config.ts).
3. **Orchestrate each resource.** The Tiltfile calls `Orchestrator.apply_service(...)`, which reaches [`tilt/resources/orchestrator/apply.star`](tilt/resources/orchestrator/apply.star). For each enabled stack it validates the resource, loads its manifest, registers the Compose resource and, for migrators, registers the migration job. The helpers are the `apply_*.star` files next to it. [`apply_compose_resource_registration.star`](tilt/resources/orchestrator/apply_compose_resource_registration.star) turns `dependsOn` into Tilt `resource_deps`.
4. **Generate the platform files.** The Docker modules under [`platform/docker/`](platform/docker/) write the files each resource needs: Compose entries in [`compose/compose.star`](platform/docker/compose/compose.star), Dockerfiles in [`dockerfile/dockerfile.star`](platform/docker/dockerfile/dockerfile.star) and the image layers in [`layers/`](platform/docker/layers/). Config generators such as `tsconfig` and Vite are in [`tilt/generators/`](tilt/generators/). Shared infrastructure (Traefik, Postgres) is loaded by [`tilt/resources/infra-loader.star`](tilt/resources/infra-loader.star).
5. **Read the generated project files.** The output lands in each resource's `.autogenerated/` folder, for example `docker-compose.app.autogenerated.yml` and `Dockerfile.app.autogenerated`. Do not edit these by hand; see [generated files](../../docs/generated-files.md).

If you change a field in `service.json`, start at step 2. If a container is built or wired wrongly, start at step 3 or 4.

## Layout

- `platform/`: Docker (`docker/`), proxy (`net/proxy.star`), shared Postgres (`state/relational.star`), secrets (`security/secrets.star`) and the local registry (`registries/local.star`).
- `tilt/manifest/`: manifest parsing helpers, validators and constants. See its [README](tilt/manifest/README.md).
- `tilt/config/`: global config, defaults, focus profiles and feature flags.
- `tilt/resources/`: databases, libraries, ordering, watchers and the orchestrator.
- `tilt/generators/`: `tsconfig`, Vite, nginx, `.npmrc` and AGENTS.md generators.
- `tilt/common/`: shared helpers used by the modules above.

Service discovery itself is in the top-level [`discovery/`](../../discovery/) folder, not in this one.
