# One Python backend on your machine

This example is one authored `service.json` and one small FastAPI service on Python 3.12. Flisk creates the local orchestration files; Docker builds the service and Tilt runs it. Edits to `src/` are synced into the running container and uvicorn reloads without an image rebuild (see [Live reload](#live-reload)). No Kubernetes cluster is needed, and you do not need Bun, Node.js, or Python installed on your machine for the service itself.

It is the Python counterpart of the [one-backend example](../one-backend/README.md). The source in `services/one-backend-python/api` is exactly what this command generates:

```bash
flisk resource api-backend --type backend --language python --stack one-backend-python
```

## Prerequisites

Install Docker (Desktop, OrbStack, or Colima), Tilt 0.25.0 or newer, and the Flisk CLI. Ports 80, 443, and 5432 must be available.

From the repository root:

```bash
cd examples/one-backend-python
flisk project --yes
flisk up one-backend-python
```

The service is routed at `http://api.one-backend-python.localhost/api/api-backend`. If port 80 is busy, Flisk picks another host port; `flisk doctor --json` reports it. Check it with:

```bash
curl --fail http://api.one-backend-python.localhost/api/api-backend/health
# {"status":"ok","service":"api-backend"}
```

Open the Tilt dashboard at `http://localhost:10350`. Stop the local stack with `flisk down`.

## Live reload

Edit `services/one-backend-python/api/src/main.py` and Tilt syncs the file into the container; uvicorn `--reload` restarts the process, with no image rebuild. Measured median save-to-ready is about 0.5 s (see [the measurements](../../docs/backend-language-providers.md#measured-the-python-dev-loop-through-flisk-up)). Changing `pyproject.toml` rebuilds the image to install the new dependencies, which is the intended behavior.

## Run the tests

The generated image has a `test` stage that runs pytest, so no local Python is needed. The image Dockerfile is generated by Flisk, so run `flisk up one-backend-python` once first (`flisk project --yes` alone does not write it). Then build the test stage from the example directory, which is the build context:

```bash
docker build --target test -f services/one-backend-python/api/.autogenerated/Dockerfile.app.autogenerated .
```
