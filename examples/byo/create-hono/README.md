# create-hono

**Stack:** a real Hono app from `create-hono` (Bun template, `oven/bun:1`)

**Notes:**
- This is for an **existing** Hono app. To start a new one inside Flisk, use the default backend: `flisk resource api --type backend`
  (Hono on Bun, no flags).
- There is another Hono example, [hono](../hono/README.md): a small hand-written app on Node with `@hono/node-server`. This one is the real
  `create-hono` output on Bun, which is what a Bun user's existing app looks like.
- The scaffolder runs at build time (`bun create hono@latest app --template bun --install --pm bun`, no prompts). The Hono version is
  whatever it resolves to.
- **Nothing needs patching.** The template exports the app (`export default app`) and Bun serves it, reading `PORT` itself. Checked: with
  `PORT=4000` it bound 4000 and answered from outside the container.
- The template answers `Hello Hono!` on `/` and has no `/health` route, so register it with `--health-path /`.
- The container runs `bun run dev`, which is `bun run --hot src/index.ts`.
- Through Flisk, Traefik sends `Host: api.<project>.localhost`; the app accepted it with no host configuration (checked through a real
  `flisk up`).

## Compared with the generated Hono backend

| | `create-hono` (this example) | `flisk resource api --type backend` |
| --- | --- | --- |
| Routes | `/` only | `/`, `/health`, `/health/live`, `/health/ready` |
| Port | Bun reads `PORT` | `process.env.PORT`, passed to `Bun.serve` through the default export |
| Dockerfile | yours (here: `oven/bun:1`) | generated by the engine (shared layers, a production stage with a health check) |
| Source changes | rebuild the image; Flisk does not sync source into a bring-your-own container (see [docs/byo.md](../../../docs/byo.md)) | the engine wires Flisk's live update |
| Prisma, NATS and other Flisk features | not applied | available through `featuresEnabled` |

Prefer the generated backend for a new service. Use this when the app already exists and you only want Flisk to run it.

## Check it

Needs Docker. Builds the image, runs it with `PORT=4000` and expects HTTP 200 on `/`:

```bash
VERIFY_WAIT_SECONDS=90 tests/e2e/resource-types/bring-your-own/verify-byo-example.sh create-hono /
```

Through a real `flisk up` and Traefik, which sends `Host: api.<project>.localhost` (needs Docker, Tilt and a built CLI):

```bash
VERIFY_WAIT_SECONDS=400 tests/e2e/resource-types/bring-your-own/verify-byo-tdk.sh create-hono /
```

## Register it in a Flisk project

```bash
flisk resource hono-api --type bring-your-own --stack shop --dockerfile ./Dockerfile --health-path / --yes
```

Use a resource name that is unique across Flisk projects sharing one Docker daemon. See
[../README.md](../README.md) and [docs/byo.md](../../../docs/byo.md) for the container contract.
